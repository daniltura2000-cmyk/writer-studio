# PROMPT: Реалізуй «СКРИПТОРІЙ» — локальний, безкоштовний, мультимовний десктоп writing-студіо

> Це технічний промпт для senior-розробника. Нижче — дослідження (≈75 підтверджених джерелами невирішених потреб письменників усіх жанрів), продуктове бачення та детальна специфікація реалізації. Пиши як продукт: не «another markdown editor», а studio-платформа, де кожен клієнтський сегмент вмикається пресетом.

---

## 1. ПІДСУМОК ДОСЛІДЖЕННЯ (навіщо це існує)

Ринок writing-софту (Scrivener, Novelcrafter, Sudowrite, Campfire, World Anvil, Aeon Timeline, Final Draft, Articy, Obsidian, Logseq, Notion) має **системні дірки**, підтверджені користувацькими скаргами та feature requests:

1. **Жоден інструмент не читає сам рукопис.** Усі story bibles — ручні. Цитата з огляду Novelcrafter: *"Whether a name is spelled one way in chapter three and another in chapter nineteen... no tool catches it."* Тому, де біль найгостріший, автори пишуть собі інструменти самі: Python-трекери статів LitRPG, Git для character sheets, власний Chrome-екстеншн для черги глав Patreon.
2. **Dialogue/narrative для ігор пишуть у трьох місцях одночасно.** AAA-райтер: *"dialogue existed in three places: in Final Draft files... in Excel files... and in a third file just called 'emergent dialogue'... every change had to be made in three different places, hundreds of times throughout production."*
3. **Barks (ambient dialogue) не має інструмента як клас.** *"the biggest nightmare was bark dialogue... 'You have to do that 10-15 different ways. And that's just an ice bomb.'"*
4. **Локалізація ігор втрачає контекст:** рядки йдуть перекладачам голими, без скріншотів/тон/перемінних; ліміти символів по мовах виявляються, коли локалізація вже зірвала дедлайн.
5. **Неанглійські автори (укр. зокрема) збирають стек з 4–5 несумісних інструментів:** Obsidian без граматики двох мов, LLM зламані для укр., глосарій серії вручну в кожен промпт, MT для прози непридатний без glossary+style.
6. **Пресети всюди DIY:** жоден інструмент не пропонує композабельні ассети (структура + чеклісти + стилі аналізу + пайплайни) як першокласний об'єкт. Scrivener — 1200-сторінковий мануал, *"getting familiar with it" becomes a form of procrastination*.
7. **Obsidian: композиційний шар мертвий** — Longform не оновлюється, нотатки не зшиваються в рукопис, немає comments/footnotes/track changes, на великих vault [[ ]]-автокомпліт 4 сек, старт 20 хв.
8. **Конфлюенс у геймдев:** *"Confluence is where documentation goes to die"* — немає інструмента між «wiki для нетехнічних» і docs-as-code, без «регресійного тестування тексту».

Повний список джерел — у файлах дослідження поруч (`writer_unmet_needs_report.md`, `fiction_author_needs_research.md`, `writer_needs_research.md`, `unmet_needs_niche_authors.md`).

## 2. ПРОДУКТОВЕ БАЧЕННЯ

**«Скрипторій»** — локальний, безкоштовний, офлайн-first десктоп (Windows/macOS/Linux) writing-студіо, яке:

- **Саме читає рукопис** — індексує його при кожному збереженні (сутності, час, числа, змінні, розгалуження) і тому може: будувати живий story bible зворотно з тексту, ловити дрейф імен/фактів/часу, перераховувати LitRPG-стат при ретроактивній правці, валідувати гейм-наратив (прапорці, досяжність, barks), контролювати локалізаційні ліміти ЗАЗДАЛЕГІДЬ.
- **Багатомовне з адекватним перекладом:** укр. та ін. мови першокласні; переклад прози = локальний пайплайн glossary + style + AI-чернетка + human proofread; нарративна пам'ять серії зберігається між томами.
- **Пресетна архітектура:** порожнє ядро + маркетплейс/бібліотека локальних пресетів (вебновел-серіаліст, романіст, гейм-наративний дизайнер, сценарист анімації, журналіст, академік, поет, перекладач, геймдев-дока, нотатник). Користувач або бере готовий пресет, або **збирає свій з ассетів**, що йому пропонуються.
- **Безкоштовно і локально:** усі LLM-функції працюють через локальні моделі (Ollama/llama.cpp), для укр. — Lapa LLM; bring-your-own-key для хмарних моделей — опція, не залежність. Жодного телеметрі-обов'язку, жодної підписки, жодного «AI-кредит-анексію».

**Ключові відмінності від конкурентів (одним рядком кожна):** Novelcrafter зберігає те, що ти ввів — ми читаємо, що ти написав. Sudowrite жереться кредитами — ми локальні. Obsidian — нотатки без композиції — ми нотатки з composer'ом. Articy — ноди без клавіатури і round-trip — ми text-first з двонаправленим імпортом. Confluence — wiki-цвинтар — ми дока з регресією тексту.

## 3. АРХІТЕКТУРА

```
┌─────────────────────────────────────────────────────────────┐
│  UI (Tauri v2 + React/TypeScript, webview)                  │
│  Режими: Писання | Біблія | Timeline | Граф наративу |      │
│  Дока/Wiki | Переклад | Пресети | Публікація                │
├─────────────────────────────────────────────────────────────┤
│  CORE (Rust):                                               │
│   • Project Store     — SQLite + markdown-файли на диску    │
│   • Index Engine      — інкрементальна індексація тексту    │
│   • Consistency Bus   — правила + алерти по всім модулям    │
│   • Preset Engine     — композабельні ассети                │
│   • Loc Engine        — мультимовність + глосарії + ліміти  │
│   • Import/Export     — DOCX/EPUB/PDF/Ink/Yarn/PO/XLIFF/MD  │
│   • Sync              — CRDT (Automerge/CR-SQLite) + релей  │
├─────────────────────────────────────────────────────────────┤
│  LOCAL AI (sidecar process):                                │
│   Ollama/llama.cpp • Lapa LLM (укр) • whisper.cpp (укр)     │
│   NLLB-200 (MT) • LanguageTool server (grammar, локально)   │
│   • dormouse-ua (укр↔en, нормалізація surzhyk) — опція      │
└─────────────────────────────────────────────────────────────┘
```

**Технічний стек:** Tauri 2 (Rust core + TS UI), SQLite (WAL), tantivy (пошук), tree-sitter/спеціалізовані парсери для структури, Automerge для CRDT-синку, Ollama як AI-sidecar, PO/XLIFF для локалізації. Markdown на диску — першокласний формат ( ніхто не «в'яже» дані в пропрієтарну хмару).

**Три залізні правила:**
1. **Markdown+SQLite на диску — єдине джерело правди.** Користувач має змогу відкрити папку проєкту блокнотом і нічого не зламати.
2. **Кожна AI-дія показує, що локально, а що хмарно.** Хмарний виклик — лише з явним дозволом і BYOK.
3. **Все, що працює локально, працює безкоштовно.** Безкоштовний tier — не триал; платні речі можливі лише як сервіси (хостинг синку, облачні моделі), а не фічі.

Це і є технічна відповідь на питання «як один продукт покриває всі жанри».

## 5. МОДУЛІ (за кластерами потреб)

### 5.1. Index Engine — «додаток, який читає рукопис» ⭐ фундамент
- Інкрементально при збереженні: NER/эмбедінг локальною LLM → entities/mentions/assertions.
- **Кандидат у власні назви:** капіталізація + частотний аналіз + відсутність у словниках мови → пропозиція «це вигаданий термін?» → реєстр з канонічним написанням. Дрейф («Kaldrin» гл. 3 vs «Kaldryn» гл. 19) → алерт з переходами до обох місць.
- **Описи/ознаки** кластеризуються по эмбедінгах: конфлікт («зелені очі» гл. 5 vs «карі» гл. 21) → конфлікт-картка з обома цитатами.
- Performance-вимога: індексація глави 3k слів ≤ 2 с у фоні; повний проєкт 500k слів — не блокує UI (фоновий воркер, прогрес-бар).

### 5.2. Живий Story Bible
- Картка сутності = агрегат усіх mentions + assertions з датами верифікації. Автор править → статус canonical; суперечливі згадки підсвічуються.
- **Правило біблії** (для анімаційних bible): твердження типу «світ: магія не оживляє мертвих» — Index Engine перевіряє кожен новий епізод на порушення правила й питає «це retcon чи помилка?».
- Експорт bible разом з рукописом (виправлення діри Sudowrite).

### 5.3. LitRPG / Progression Engine
- Стан персонажів = snapshot-модель подій: глава має дельти («+2 рівня», «−30 HP», «отримав X»). Формули шаблонами (`level = f(xp)`).
- Ретроактивна правка в гл. 5 → перерахунок усіх снапшотів + діф-звіт по кожній главі. «Stat Sheet preview як читач бачитиме в гл. N». Ретроактивний «stat-error radar».

### 5.4. Retcon Manager (draft/published гілки)
- Публікація глави = фіксація версії. Далі diff draft vs published = **retcon-зобов'язання**.
- Правка факту в гл. 5 → Index Engine будує список усіх залежних згадок у пізніших главах → черга ревізій з переходами (один клік = «переглянув»).

### 5.5. Timeline Engine
- Парсер часових маркерів («наступного ранку», «через три дні») + календар світу (фентезійні календарі підтримуються).
- Алерти: персонаж не встигає доїхати; знання, здобуте пізніше, згадане раніше; мертвий персонаж у сцені.
- **Локаційний календар персонажів** («хто де і з ким» по главах) — заміна костиля «Google Calendar для персонажів».

### 5.6. Серійний Командний Центр (вебновели)
- Kanban глав: draft → edit → buffer → scheduled → published, по всіх творах.
- Прогноз вичерпання буфера з фактичної швидкості (ковзне середнє слів/день).
- **Crosspost Orchestrator:** один канонічний markdown → адаптери платформ (RoyalRoad, ScribbleHub, Wattpad, AO3, Patreon). Реалізація: вбудований Playwright-контролер локального браузерного профілю, або офіційні API там, де є. Атомарний журнал: яка версія глави де опублікована. Правка канону → диф по платформах → вибіркова перевідправка.
- **Patreon Tiers Planner:** глава → набір тірів (early access), сітка перетягування, інтро-пости, офіційний Patreon API v2.
- **Recap Generator:** з Index Engine збирає recap по book-boundary (події, нові персонажі, зміни статів) — заміна десятків ручних recap-глав на RR.

### 5.7. Game Narrative Studio ⭐ (найменше покритий ринок)
- **Text-first, keyboard-first:** діалог пишеться як текст (Ink/Yarn-сумісний синтаксис), граф наративу — похідна візуалізація, не основний редактор. Противага mouse-heavy Articy (*"I couldn't get into a writing rhythm"*).
- **Barks як першокласний об'єкт:** таблиця `barks` (тригер, умови, пріоритет, cooldown, 10–15 варіантів). UI: вибирай тригер → пишеш варіанти списком → перевірка дублів/тону між варіантами. Експорт у CSV/JSON для движка. Ніхто в індустрії цього не має — усі сидять в Excel.
- **Single Source of Truth:** той самий рядок діалогу доступний як: текст сцени (катсцена), рядок у bark-таблиці, рядок для движка. Зміна в одному місці = зміна всюди (з diff-звітом).
- **Auditor змінних:** матриця set/check по прапорцях (заміна ручного *"simple sheet with a single row for each variable"*), мертві прапорці, недосяжні ноди, опечатки у змінних (Yarn лише warning — ми error з переходом).
- **Round-trip:** імпорт .ink/.yarn/.json Articy → робочі документи; експорт назад. Зміни, зроблені в коді гри (git diff імпортованого файлу), підсвічуються як «вхідні правки» для прийняття/відхилення — заміна *"I'd need to retype everything by hand... soul-crushing"*.
- **Локалізаційні ліміти ЗАЗДАЛЕГІДЬ:** у редакторі діалогу під кожним рядком — смужки лімітів по всіх цільових мовах (ен+30% для нім., CJK-стиснення). Алерт при перевищенні ЩЕ В РАЙТЕРА, не після локалізації.
- **Контекст рядка подорожує з рядком:** до кожного `string` — хто/кому/тон/скріншот-слот/перемінні. Експорт PO/XLIFF з контекстом; імпорт перекладених рядків назад у правильні ноди.

### 5.8. Animation Writer
- **Show Bible як база знань** (5.2) — персонажі/світ/правила/арки, пов'язані з епізодами.
- **Структурний валідатор епізоду:** пресет «анімаційний 20-хв епізод» = cold open + 2 narrative turns + hook; Boundary-сцени перевіряються по розмітці; алерт «немає cold open», «3 діалогові сцени підряд — для анімації це червоний прапор».
- **Мют-тест:** сцена без діалогів → біти-кадри з action lines → «animatic strip» для перевірки *"watch it with the sound off"*; експорт у Flashboards-стилі сторіборд-лист.

### 5.9. Docs Studio (геймдев/технічна документація)
- Живий wiki-режим над тими ж структурами: сторінки, простори, беклінки (як Obsidian, але швидкі — tantivy, не повне завантаження в пам'ять).
- **Регресія тексту:** після N правок сторінка позначається на «перечитання» — диф проти останнього рев'ю + чекліст «чи новий читач досі зрозуміє X, Y, Z». Лікує *"Confluence is where documentation goes to die"*.
- **Docs↔код:** links до файлів коду/тасок (GitHub/Jira через локальні API або імпорт); алерт «сторінка описує модуль, який змінювався після останньої рев'ю доки».
- **Статус-фрешність:** кожна сторінка — last-verified дата + owner; дашборд «застаріле».

### 5.10. Notes → Manuscript Composer (Obsidian-сегмент)
- Атомарні нотатки + **Draft Composer:** нотатки перетягуються в outline глави; живий двонаправлений зв'язок нотатка↔абзац рукопису (правиш абзац — бачиш звідки нотатка; правиш нотатку — бачиш куди вона пішла). Лікує *"my atomic notes didn't fit [the writing]"*.
- **Comments/Footnotes/Track changes** для рукопису (word-процесорне рев'ю поверх markdown) — *"I use comments and footnotes... cannot replicate in Obsidian. Kind of a huge bummer!"*
- **Manuscript Export:** пресети вимог видавців (відступи, інтервал, пагінація), paginated preview, DOCX/EPUB/PDF — без Pandoc-L knowledge.
- **Performance:** tantivy-індекс, lazy loading — навмисно проти Obsidian-хвороби (старт 20 хв, автокомпліт 4 с на великих vault).

### 5.11. Журналістика / нон-фікшн
- **Source CRM:** об'єкти Джерело/Інтерв'ю/Цитата; дедуп питань (*"inadvertently asked the same question twice"*); on/off-record прапорець на фрагменті, off-record фізично не йде в хмарний експорт.
- **Quote Verifier:** whisper.cpp локально; цитата в статті ↔ сегмент аудіо ↔ транскрипт, тричі пов'язані; статус verified тягнеться в драфт.
- **Pitch Lifecycle:** idea → pitched → follow-up due → commissioned → filed → paid; база норм фолоу-апів по виданнях.
- **Fact Ledger:** твердження про реальний світ вимагає citation або flag; звіт «unverified» перед здачею.
- **Content Decay Monitor:** датовані твердження повертаються з віком («цифра 2024, тобі 18 місяців»).
- **Response-to-Reviewers** (академія): коментар рецензента → зміна → відповідь → автогенерація response-листа.

### 5.12. Поезія / комікси / IF / переклад
- **Poetry Mode:** офлайн CMU-аналог + укр. складорозділ; жива скансія і схема рим у редакторі; формові шаблони (сонет, вілланель) з рахунком слотів.
- **Comics Scripter:** PANEL-структура (опис, діалоги, caption/sfx/balloon, word-limits), експорт PDF художнику + letterer-список. «Final Draft для коміксів», якого просять прямо в лоб.
- **IF Mode:** text-first (як 5.7) + **Playtest Runner:** автопрогін усіх гілок зі всіма станами змінних → звіт broken links, недосяжні сцени, undefined vars. Лікує *"you have to try all of the combinations"*.
- **Translator Studio:** див. §6.

### 5.13. Публікація & самвидав

## 6. ПРЕСЕТНА СИСТЕМА ⭐ (ключова вимога замовника)

Ядро порожнє; кожен жанр = пресет. Пресет = маніфест + пакети ассетів:

```yaml
preset: webnovel-serial-ua
assets:
  entities:      # типи сутностей з кастомними полями
    - {name: персонаж, fields: [рівень, клас, статус, арка]}
  structure:     # шаблон структури твору
    - {book: [arc: [chapter: [scene]]]}
  checklists:    # при списках перевірок
    - {name: перед-публікація, items: [consistency-scan, limits-scan, recap-update]}
  validators:    # увімкнені правила Index Engine
    - [name-drift, on] [timeline, on] [stat-radar, on]
  templates:     # текстові шаблони
    - {recap, chapter-note, author-comment}
  ai_recipes:    # локальні AI-рецепти
    - {name: recap-uk, model: lapa, prompt_ref: recipes/recap_uk.txt}
  pipelines:     # автоматизації
    - {on: chapter_publish, then: [crosspost[RR], crosspost[Wattpad], patreon-tiers]}
```

**Вимоги:**
- **Бібліотека ассетів:** у UI користувачbrowse'ає категорії (структури, чеклісти, валідатори, шаблони, AI-рецепти, пайплайни, стилі аналізу) і збирає власний пресет з будь-яких ассетів — комбінація типу «structure з вебновел-пресету + чекліст з академічного + валідатори LitRPG».
- **Вбудовані пресети MVP:** вебновел-серіаліст (укр), романіст, гейм-наративний дизайнер, сценарист анімації, журналіст, академік, поет, перекладач прози, геймдев-дока, нотатник/Zettelkasten.
- **Спільнота:** пресети — прості JSON/YAML файли, імпорт/експорт файлом; локальний «маркетплейс» з git-репозиторію (за бажанням, без центрального сервера).
- Порожній старт = інтерв'ю-онбордінг: «що пишеш?» → пропонує 1 пресет + показує, з чого він складається, і дозволяє одразу редагувати.

## 7. МУЛЬТИМОВНИЙ РУШІЙ ⭐ (ключова вимога замовника)

**Першокласні мови:** українська та англійська як еталонні; далі — все, що дає NLLB-200 (200 мов) і LanguageTool (25+ мов grammar).

**7.1. Мова проєкту й змішані мови**
- Мова проєкту/глави/навіть абзацу; spellcheck+grammar переключаються автоматично (LanguageTool server локально, multi-lang правила одночасно — лікує *"On macOS it often offers no suggestions when you write in more than one language"*).
- Діакритики, кирилиця+латиниць гібриди, surzhyk-нормалізація (dormouse-ua), translit-пошук («rid» знаходить «ряд»).

**7.2. Переклад прози (не MT-сирець)**
Пайплайн «локальна чернетка + людина фінально»:
1. **Серійний глосарій** (`glossary`, series_wide): імена, вигадані терміни, правила транслітерації vs перекладу; зберігається між томами — лікує *"Alice becoming Elise by chapter four"* і *"the constant need to reinsert glossaries"*.
2. **Narrative memory:** попередні томи серії — як локальний контекст (резюме персонажів/арок з Index Engine, не повний текст).
3. **NLLB-200 або локальна LLM** (Lapa для укр) дає чернетку з глосарієм-примусом (glossary-constrained decoding: пост-валідація термінів).
4. **Style pass:** локальна LLM з пресетним style-рецептом (ритм, гумор, реєстр ти/ви — окрема перевірка T-V, бо *"the reverse model picks a register at random"*).
5. **Side-by-side proofread UI:** оригінал/переклад абзац-за-абзацом, коментарі, статус рядка: draft → mt → human → approved.
6. **Локалізаційні ліміти** з 5.7 застосовуються і тут (ігрові рядки, субтитри).

**7.3. Стек локальних моделей (провірено дослідженням):**
| Задача | Інструмент | Примітка |
|---|---|---|
| Укр. генерація | Lapa LLM v0.1.2 (Ollama `uamarchuan/lapa-v0.1.2-instruct`, Gemma3 12B, 128K ctx) | найкраща відкрита укр. LLM |
| Укр. STT | whisper large-v3 + Yehor fine-tune (WER 12.75%) | github.com/egorsmkv/speech-recognition-uk |
| MT | NLLB-200 (+ fine-tune via OpenNMT) | baseline укр |
| Grammar | LanguageTool server (укр підтримка) | локально, без хмари |
| Укр↔en бридж, surzhyk | dormouse-ua (pypi, 76M MT, CPU) | опційно |
|Spell/словник | Goroh + dmklinger Ukrainian dictionary | локальні словники |

**Обмеження чесно:** малі локальні моделі (3B) ламають укр. орфографію, embedding-моделі для укр. слабкі — тому мінімальна рекомендована конфігурація: 7B+ квантована Lapa; UI попереджає про якість моделі per-задачу. Whisper плутає укр/рос на кириличному міксі — тому мова аудіо задається вручну за замовчуванням проєкту.

**7.4. Багатомовна публікація**
- Паралельний текст (двомовна книга) — layout-шаблон паралельних абзаців → EPUB; лікує *"KDP does not have a bilingual format... Calibre process quite complex"*.
- Мовні теги творів при експорті на платформи (лікує AO3/Wattpad-скарги на code-switching без позначки).

## 9. КРИТЕРІЇ ПРИЙМАННЯ (acceptance tests)

1. **Consistency:** у проєкті 100k слів змінюй ім'я персонажа в гл. 3 → за ≤ 10 с отримай список усіх згадок у главах 4–40 з diff-попередженнями; жодне місце не пропущено (перевірка проти mentions-індексу).
2. **LitRPG:** зміни XP в гл. 5 → усі stat sheet-и гл. 6+ перераховано; діф-звіт показує кожну числову зміну.
3. **Crosspost:** публікація глави на RR + ScribbleHub + Wattpad однією дією ≤ 2 хв з першим налаштуванням; журнал показує статус кожної платформи; правка канону пропонує повторну відправку з diff.
4. **Barks:** створи bark з 12 варіантами, тригером, cooldown; експорт CSV — валідний для імпорту в умовний движок; дублі-варіанти піймані.
5. **Локалізаційні ліміти:** рядок, що перевищує німецький ліміт при +30%, підсвічений в редакторі ДО публікації; PO-експорт містить контекст.
6. **Укр.:** текст українською 5k слів — grammar-перевірка локально (LanguageTool), без жодного хмарного виклику (перевірити сніфером); переклад гл. укр→en зі серійним глосарієм — усі терміни глосарію відтворені точно.
7. **Пресети:** новий користувач за ≤ 5 хв обирає/збирає пресет і пише перший абзац; пресет-файл імпортується/експортується як один JSON.
8. **Офлайн:** відключи мережу — всі функції, крім crosspost/публікації, працюють; синк відновлюється без конфлікт-файлів після повернення мережі.
9. **Продуктивність:** старт ≤ 3 с на vault 1M слів; автокомпліт посилань ≤ 100 мс (tantivy).
10. **Метадані:** EPUB, експортований під pen name, не містить справжнього імені ані в XMP, ані в шляхах (автотест).
